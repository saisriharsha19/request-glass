# Tuckday deployment and calendar connections

Tuckday is the new public name. Existing internal IndexedDB keys, account database, record IDs and calendar event IDs are preserved so a name change does not destroy or duplicate saved data.

The live frontend is https://tuckday.pages.dev. Cloudflare Pages authorization was completed. `bun run deploy:pages` builds the allowlisted static frontend and a same-origin API gateway. The existing `return-radar` Worker remains the backend for native accounts, D1 and NIM; no second account database or authentication provider is introduced. Existing workers.dev and Render addresses remain reachable. Signing in at the new origin uses the same username/password, but browser cookies and guest storage are origin-specific. Export/import guest records before moving if needed.

Deploy the backend first (`bun run deploy:cloudflare`), then the frontend (`bun run deploy:pages`). Apply both `0002_calendar_subscriptions.sql` and `0003_calendar_sources.sql` to D1 before enabling calendar connections. The Pages gateway rejects cross-origin writes before translating the validated origin for the backend. It forwards host-only session cookies, does not expose provider credentials and keeps private subscription URLs on the frontend origin.

Calendar → Connect calendar now brings external ICS calendars into Tuckday. Add a named source using Outlook’s published ICS URL, Google’s iCal URL or iCloud’s published URL. Up to ten sources are stored per account. Timed and all-day events, recurring events, moved exceptions and cancellations appear together in the month grid and agenda, with a calendar filter and source labels. Edits remain in the source calendar. The cache covers 31 days back and 366 days forward, up to 1,500 occurrences per feed. Source files are limited to 1 MB / 3,000 event components and are discarded after parsing. Provider URLs are restricted to supported HTTPS calendar endpoints; redirects are not followed. Private feed URLs are not returned in list responses or sent to AI.

Background scheduling runs every five minutes and refreshes a batch of ten sources that have not been attempted for fifteen minutes. Refresh calendars checks immediately, with a one-minute per-source minimum interval. Larger queues can take longer. Last successful snapshots survive provider failures; deleted/changed events replace the old snapshot on the next successful refresh.

The secondary “Send Tuckday reminders to another app” option creates a private read-only subscription link, with provider-specific steps for Google, Outlook and Apple. Future reminders are fetched from D1, independent of whether either device is online. The link exposes reminder titles/dates, not receipt text, notes or source files. Disconnect revokes future access; calendar applications may keep previously fetched events until the subscription is removed. Updates follow the provider's refresh schedule and may take hours. This is not OAuth account linking or two-way calendar editing.

Official setup references: [Google Calendar](https://support.google.com/calendar/answer/37100?hl=en), [Outlook](https://support.microsoft.com/en-us/outlook/import-or-subscribe-to-a-calendar-in-outlook-com-or-outlook-on-the-web), [Cloudflare Pages advanced mode](https://developers.cloudflare.com/pages/functions/advanced-mode/).

Sync now displays an in-progress state and a server-confirmed record count. Failed initial account loading retries without requiring a page reload. The sidebar reflects the signed-in account rather than showing guest instructions. A bounded browser-storage open prevents account startup from hanging forever behind IndexedDB. A receiving browser can reconnect and retrieve a save after the writer has closed; tests cover this sequence as well as failed startup recovery.

AI document assistance additionally recognizes explicitly dated bill payments and document renewal/expiry reminders, with quoted evidence. Relative periods and unsupported dates are still omitted for review.

Verification: TypeScript, 35 unit tests and 40 browser tests passed. A real public Google feed produced 30 events on the deployed backend and at tuckday.pages.dev; a second signed-in browser retrieved the connected calendar after the first browser closed. Synthetic accounts were deleted. Personal Outlook/iCloud feeds have not been tested; add each private link through the signed-in UI.

Calendar source lists now return metadata only. Events use an account-scoped cursor endpoint (100 per page, maximum 64-day query); the frontend requests the visible month grid with timezone padding and reveals 50 cards at a time through Load more. Connected agenda events follow the displayed month; native reminders retain their all-date view. Day counts reflect loaded events when further pages exist. Device-local start/end times identify ongoing and ended events, including same-day meetings and all-day exclusive end dates. Safe HTTP(S) meeting links are extracted from URL, description and alternate HTML fields and shown as links; descriptions render as plain text. Older snapshots gain links at the next successful refresh. Mobile titles wrap within cards and inputs remain at least 16px.

Follow-up: dropdown controls now share a 16px type scale and 48px minimum height, with full-width phone layouts. URLs are linkified directly in locations, descriptions and imported reminder notes, including cached events without a links array. Calendar ingestion also extracts location URLs and handles www addresses and HTML-encoded queries. Browser coverage includes actual link navigation and control measurements at 320, 390, 768 and 1280px.

Mobile modal follow-up: corrected a full-width checkbox that made Add purchase horizontally scrollable. Dialog grids and flex children can shrink, forms use dynamic viewport height, and input-method buttons no longer focus/jump to a different form section. All four dialogs passed horizontal scroll checks at 320/375/390px and shortened viewport heights in Chromium mobile emulation. WebKit could not run because this host lacks its system libraries; no real iPhone keyboard test is claimed.

AI/PDF follow-up: the form now accepts reminderLabel and source-supported event notes, displays filled calendar dates, accepts exact descriptive string fields returned by NIM, and rejects unsupported purchase dates/amounts. Default structured extraction uses Nemotron 3 Super, verified against the live NIM API with a synthetic appointment. PDF reading retains page labels and link annotations, falls back to OCR for sparse/broken text, and supports up to 50,000 input characters consistently. Event times/locations remain notes on native all-day reminders; timed external calendar events retain their existing support. Originals remain temporary.

Navigation/state follow-up: the sidebar is now the only Records / Calendar / Insights switcher. Coming up and Archived are local record views; redundant calendar/CSV shortcuts were removed. Page headings and aria-current reflect the active section, and purchase totals stay on Records. Workspace changes and record views use browser history. Validated, versioned per-account sessionStorage remembers search/filter/sort, visible record limit, calendar month/day/source/filter, and scroll positions within the current tab. URL hashes expose only the workspace name. Uploaded files, receipt text, AI results and form drafts are excluded from navigation storage; no new database tables or API fetches are introduced. Invalid saved state falls back safely; history entries from a different account cannot restore that account's filters.

Unified form follow-up: upload and pasted text now share one optional source area; manual fields are always present. Item and Favorites are at the top, with a full-width checkbox row. Mobile and desktop layout checks cover Records, Calendar, Insights, account and all dialogs at 320/390/768/1280px. New and edited drafts are scoped to the account and browser tab; closing preserves editable values, reload can reopen an active draft, Save/Discard removes it. Saved-record changes invalidate stale edited drafts. Source text, PDFs and page images are excluded from draft persistence.

AI now maps explicit model date keys (including priceCheckDate) into all supported form fields and adds category classification. A real NIM text test returned all six dates, category and reminder name in one provider request. An image-reader failure can fall back to usable extracted text within the same user action, with a visible notice; structured output gets at most one correction pass. Failed/empty results retain temporary images while the dialog stays open. Provider requests are bounded by a 90-second total, and cancellation still prevents late form changes. Manual edits are preserved by both local and AI extraction.
